# 正式数据、备份与清理执行流程

当前只有自建合成数据，尚未接收正式平台数据；没有启动定时删除或执行数据删除。以下流程供正式任务前填写和执行。

## 任务登记（不要填密钥或原文）

| 字段 | 任务开始前/完成后填写 |
|---|---|
| Run/Job ID、绑定 commit、镜像 digest | 取得正式任务后填写 |
| 责任人、授权访问者 | 用户在本地填写 |
| 开始/完成时间 | ISO 8601，写清 UTC+8 |
| 数据到期日 | 完成时间加 30 天；另有平台书面许可时记录许可编号与期限 |
| 实际 user_id 清单 | 在受控位置登记，仅用于本任务范围；勿公开原始清单 |
| 主库、volume、备份、快照、导出、派生文件 | 逐项写实际受控存放位置；无副本写“无”，不能默认所有位置都无副本 |
| 日志、监控、追踪 | 核实无正文/凭据记录，检查导出和访问范围 |

平台内容及派生副本仅用于当前任务，限制授权访问；不用于训练、分析、重建数据集或公开展示。官网要求完成后 30 天内删除，延长须平台书面同意。[官方数据责任说明](https://agentmemoryleaderboard.ai/api-guide)

## 备份与恢复验收

正式任务确需备份时，使用受控加密存放位置，登记副本、权限和到期日。不要把官方数据的 pg_dump 放进源码包、Git 或公开报告。恢复应使用独立隔离库和相同 pipeline 签名，验证消息/片段/来源计数、幂等及搜索，再决定切换。正式部署环境的完整恢复验收尚未完成。

本地验证补充：2026-10-06 已对自建合成库完成 dump→独立临时数据库恢复，五张表计数及全行一致性指纹相同；临时数据库已移除，现有库未改动。记录见 `evidence/20261006-memory-local-closeout/backup-restore.json`。这是数据库恢复一致性检查，未以恢复库完成 HTTP 搜索、故障切换或整机恢复；上段正式流程的全面验收仍待最终部署时完成。

## 到期清理和核对

1. 核实任务已结束，精确核对该任务用户列表，确认没有仍运行的相关任务；记录责任人和日期。
2. 对核对后的每个 user_id 运行已有 `scripts/memory_admin.py purge-user`，传入完全相同的 `--user-id` 与 `--confirm-user-id`。删除会级联移除请求、消息、片段和来源；不要按模糊前缀批量删库。
3. 在主库只读计数检查该用户的四张业务表均为 0。删除备份、快照、导出与派生副本，并在副本清单逐项确认。主库 DELETE 不等于所有副本已清理。
4. 保存脱敏审计：任务标识、执行时间、责任人、各存放位置处置状态和清理后计数。不保留正文、令牌或足以重建评测数据的输出。

本流程是执行准备，尚无正式数据、到期日期或实际清理验收。不会未经用户指示自动删数据或替用户发送消息。
