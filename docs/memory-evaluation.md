## 合成数据

`evals/build_memory_cases.py` 可复建同一版本数据：60 道开发题、40 道留出题。用户/会话不跨两个文件共享。涵盖编号、中文/英文、跨会话多证据、时间更新、同名跨用户、无答案、长文末尾与省略表达，每题带 24 条同用户干扰消息。

这是少量模板变体构成的**诊断起始集**，标签是明确关联到原文的合成预期，不是人工审定的正式金标。留出集采用相同模板类别，代表性有限；即使高召回也不能证明官方水平。正式申请前应人工抽查，并增补真实但有授权来源的更多样自建对话；不得引入平台私有数据。

## 算法与指标

`memory_eval.py` 向真实服务 Add，然后 Search(top_k=100)，逐题统计：

- Evidence Recall@5/20/100；多种可接受证据组合取覆盖最多的一组。
- 完整证据覆盖率（目前包含单证据及多证据题）；可根据逐题 category 单独聚合跨会话/时间/省略题的多证据覆盖。
- 来源越界/用户泄露数；返回原文与 source offsets 不一致的审计错误数。
- 无答案题召回数量单独报告，不给无答案题虚假的满分 Recall。
- Search 延迟 P50/P95，失败题数、结果条数、逐题证据，数据/源码哈希及本地配置摘要。

长文题须找回包含标注 quote 的切片，不能只命中同消息的无关开头就算成功。期望来源通过 message_id 重建并核对，不拿关键字“看起来像答案”当正确证据。只允许自己的合成数据保留这些原始输出。

HTTP 输出无法证明数据库没有重复记录，因此报告明确写 `duplicate_database_writes=not_measured_by_HTTP_evaluator`。真实数据库测试使用表计数验收重复写入；协议失败归到 failed，错误类型脱敏，失败题不会被冒充有结果。

## 固定比较流程

1. 运行 vector 开发集，保存唯一输出路径、源码/数据哈希及配置。
2. 仅将 MEMORY_RETRIEVAL_MODE 切为 hybrid，重启，再用相同数据和明确 namespace 运行；相同 namespace 可利用幂等写入，避免重复 Add 计费。
3. 比较跨会话、编号、中文各类别的收益、退步、Search P95 和用量；不要因 Top100 看起来全覆盖就判断有效。
4. 选定参数后一次留出验收，失败与退步都披露；没有真实收益时保持 vector。
5. 冻结后重新执行公网和平台 Smoke，再考虑 Full。

配置摘要来自评测进程的环境；远程服务器必须另外保存实际环境的脱敏摘要并核对，不能把本机设置当成线上配置证据。评测脚本默认生成独立本地测试 user namespace，并把它保存在报告中，以便精确清理；不与官方数据混用。

运行指南见 `memory-deployment.md`。本地诊断集和同用户 1000 条串行样本已测量；更大规模、并发、峰值内存、独立存储增长及费用仍待实测，无官方成绩。
