# 分流缺陷修复与回归验收

2026-10-03，Codex 辅助完成并更新运行中的 Compose API。原始 `stage5-baseline.json` 保留不变。

## 改动

- 删除“我”和“发货”同时出现就判定个人订单的宽泛条件，改为识别“我买的”“我购买的”“我这一单”等个人购买表达；“我想了解发货规则”进入 FAQ。
- 明确退款意图优先于附带订单号。缺退款号时追问，未知退款号时转人工；不会借用订单记录回答退款问题。
- 问题包含“我的订单”但实际询问退款且已给退款号时，不再额外要求订单号。
- 显式人工请求保持最高优先级；纯订单查询及原有四字段响应保持一致。

两个原失败的实际结果：

- `first-person-policy`：返回 `faq_rag`，说明 2 个工作日、周末及法定节假日例外、预售依据，并引用 `RULE-SHIPPING-01`。

## 语义复核与边界

助手检查了本轮全部固定集输出以及 8 个新增问法。路由修复符合预期，但 **46/46 指自动检查，并不代表所有语义条件都完美保留**：

- `RULE-RETURN-03-paraphrase` 和 `two-rules` 中提到质量/错发运费由店铺承担时，没有明确重复“店铺核实”的条件；虽然保留争议人工核查，条件完整性仍应改进。
- `RULE-REFUND-02-exact` 回答原路退回渠道时，省略了“审核通过”的前提；未承诺具体退款已执行，但也应纳入条件完整性测试。

上述 3 题记录为语义条件省略，不修改本轮输出或题集来掩盖问题；这轮只修复两处路由缺陷。后续生成质量改进应增加可检查的条件断言和独立问法，而不能只优化路由通过率。

分流仍基于有限关键词和正则，未实现通用意图理解、多事项组合查询或从正文提取单号。新问法为助手辅助编写的回归用例，非独立盲测。没有真实订单系统和工单执行能力。
